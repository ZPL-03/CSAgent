# CSAgent 接口约定

## 任务

自然语言入口接受工作压力和可选的长度、半径等约束。候选总数和预筛保留数未指定时分别为 `null`，在生成前、预筛前通过聊天询问。等待节点为 `awaiting_candidate_count` / `awaiting_screen_count`，对应 `pending_confirmation=candidate_count` / `screen_count`；`provide_quantity` 校验回答并写回同一任务与快照。用户明确给出的长度、半径、厚度或铺层角默认写入 `fixed_geometry`，作为候选生成、代理初筛和有限元输入必须满足的几何条件；只有字段附近出现“约、参考、附近、设计中心、左右”等参考语义时，对应字段才写入 `geometry_reference`。字段级表达如“长度固定 500 mm”“半径必须等于 100 mm”“厚度限定 10 mm”同样属于固定几何约束。

示例任务：

```json
{
  "application": "复合材料外压圆柱耐压壳",
  "load_conditions": {
    "type": "external_pressure",
    "label": "外部静水压力",
    "external_pressure_MPa": 30.0
  },
  "boundary_conditions": {
    "type": "END_CLAMPED",
    "label": "两端固支"
  },
  "geometry_envelope": {
    "length_mm": [300.0, 800.0],
    "radius_mm": [80.0, 180.0],
    "thickness_mm": [5.0, 20.0],
    "alpha_deg": [10.0, 80.0],
    "beta_deg": [10.0, 80.0],
    "imperfection_ratio": [0.008, 0.008]
  },
  "candidate_generation_preferences": {
    "total_candidates": 12,
    "llm_candidates": null,
    "case_transfer_candidates": null,
    "doe_candidates": null,
    "source_allocation_mode": "ratio_2_1_1"
  },
  "screening_preferences": {
    "top_k_candidates": 5
  },
  "user_input_facts": {
    "candidate_generation": {
      "total_candidates": 12,
      "top_k_candidates": 5
    },
    "application": "复合材料外压圆柱耐压壳",
    "load_conditions": {
      "type": "external_pressure",
      "external_pressure_MPa": 30.0
    },
    "design_targets": {
      "ultimate_pressure_min_MPa": 35.0
    }
  },
  "hull_type": "CYLINDRICAL",
  "design_targets": {
    "ultimate_pressure_min_MPa": 35.0,

```

`candidate_generation_preferences` 和 `screening_preferences` 是主流程必需控制参数。`total_candidates` 和 `top_k_candidates` 由自然语言任务明确给出。`llm_candidates`、`case_transfer_candidates`、`doe_candidates` 在自然语言入口保持 `null`，候选生成阶段按 `source_allocation_mode=ratio_2_1_1` 和 `config/app_config.yaml` 计算初始来源配额。

`user_input_facts` 只保存用户自然语言明确给出的事实。系统内部工程域参数用于 DOE、规则检查、候选变量完整性和有限元接口；候选生成 LLM 不把这些工程域参数读取为用户事实。LLM 输入包含 `user_input_facts`、合并 RAG/KG 检索片段、当前 LLM 候选数量、输出字段要求和系统候选字段约束。

## 知识库/知识图谱

运行时入口为 `core.domain_knowledge.DomainKnowledgeBase`。配置项读取 `config/app_config.yaml` 的 `project_knowledge`：

- `base_dir`: `knowledge/runtime`
- `upload_dir`: `knowledge/runtime/uploads`
- `builtin_dir`: `knowledge/csllm`
- `builtin_rag_chunks_path`: `knowledge/csllm/rag/rag_chunks.compact.jsonl.gz`
- `builtin_kg_dir`: `knowledge/csllm/kg`
- `builtin_manifest_path`: `knowledge/csllm/provenance/manifest.json`
- `builtin_retrieval_index_path`: `knowledge/csllm/rag/retrieval_index.sqlite`，显式配置后文件缺失直接报错
- `builtin_dense_enabled`: 内置索引语义召回开关，默认启用；关闭时只使用 BM25
- `rag_chunks_path`: `knowledge/runtime/rag/rag_chunks.jsonl`
- `kg_dir`: `knowledge/runtime/kg`
- `manifest_path`: `knowledge/runtime/manifest.json`
- `structured_dir`: `knowledge/runtime/structured_text`
- `chunk_token_size`: RAG 分块目标 token 数
- `chunk_overlap_tokens`: 相邻 chunk 重叠 token 数
- `min_chunk_tokens`: 小 chunk 合并与质量控制参考阈值
- `vector_enabled`: 是否写入并检索项目知识向量 collection
- `vector_chroma_dir`: 项目知识向量索引目录，当前为 `knowledge/chroma_db`
- `vector_collection_name`: 项目知识向量 collection，当前为 `csdm_cph_project_knowledge`
- `vector_top_k_multiplier`: 向量候选召回倍数，融合去重后再截断为 `top_k`
- `vector_ready`: 入库服务表示用户增量 collection 已写入；检索服务和 GUI 合并状态表示内置或用户增量向量可用
- `vector_status`: 向量索引真实状态，取值为 `pending`、`success`、`warning` 或 `failed`
- `vector_message`: 面向 GUI 和审计的向量索引状态摘要
- `vector_detail`: 向量后端、目录或失败原因摘要
- `vector_backend`: 实际使用的嵌入后端，失败时为 `unavailable`

`status()` 返回内置数据、用户增量和合并总数：`builtin_ready`、`builtin_rag_chunk_count`、`builtin_kg_entity_count`、`builtin_kg_relation_count` 表示 `knowledge/csllm`；`runtime_document_count`、`runtime_rag_chunk_count`、`runtime_kg_entity_count`、`runtime_kg_relation_count` 表示用户上传增量；`rag_chunk_count`、`kg_entity_count`、`kg_relation_count` 表示最终合并后的总 RAG/KG。

`DomainKnowledgeBase.status()` 还返回 `builtin_generated_at`、`builtin_source_count`、`builtin_index_ready`、`builtin_vector_ready`、`builtin_vector_status`、`builtin_vector_chunk_count` 和 `runtime_vector_chunk_count`。内置向量可用要求矩阵形状、数据类型和编码契约匹配且本地模型快照可定位，不代表已执行当前查询。GUI 使用 `merge_knowledge_status()` 保留入库服务的五阶段流水线，汇总两类向量数量，任何一类报告失败或警告时不显示整体绿色。真实查询仍校验模型名称、向量维度和有限值；编码失败抛出异常，不静默切换为纯关键词结果。

内置检索以逐查询只读 SQLite 连接执行 BM25，向量矩阵使用只读内存映射。BGE-M3 查询编码与索引的归一化 CLS、1024 token 窗口、128 token 重叠及去重 token 加权聚合契约一致。BM25 与 dense 结果通过 RRF 融合，保留 `chunk_id`、`record_id`、来源字段和 `retrieval_sources`，后者区分 `BUILTIN_BM25` 与 `BUILTIN_DENSE`。用户增量 JSONL、Chroma 与内置命中在统一入口按来源去重，KG 关系保留文本证据引用。

资料入库入口为 `core.knowledge_ingestion.KnowledgeIngestionService.ingest_file(path)`。该接口接收用户上传资料路径，返回 `IngestionResult`，字段包含 `document_id`、`parser_backend`、`markdown_path`、`chunk_count`、`entity_count`、`relation_count`、`duplicate_chunk_count`、`retrieval_verification` 和五阶段流水线状态。五个阶段为 MinerU / Docling 文档解析、语义分块、BGE-M3 向量化索引、KG 实体/关系抽取、检索验证 / 证据引用。文件类型契约由 `SUPPORTED_INGEST_SUFFIXES` 定义，GUI 文件选择器使用同文件的 `SUPPORTED_QT_FILE_FILTER`，避免 GUI 与解析器支持范围漂移。PDF、DOCX、PPTX 和图片优先调用 MinerU / Docling；PDF 会依据文本层密度选择 MinerU pipeline 文本路由或 high-accuracy 路由；外部解析器不可用时，PDF 使用 PyMuPDF 文本层解析，DOCX/PPTX 尝试文本层解析，图片保留资料元数据。Markdown、文本、JSON/YAML/TOML/INI、CSV、TSV、XLSX/XLSM、Abaqus 输入、子程序、日志、状态和消息文件由本项目解析器转换为 Markdown。ODB、SIM、CAE 等工程二进制文件只写入可检索元数据，内部场变量和云图由 FEM 可视化链路读取。文档编号由文件 SHA256 生成；同一文件重复入库替换同一文档记录。RAG 文本块按 `content_hash` 去重，`chunk_token_size`、`chunk_overlap_tokens` 和 `min_chunk_tokens` 共同控制文本块窗口、重叠上下文和小块合并；去重后的用户增量 chunk 写入 `rag_chunks.jsonl`，并同步重建项目知识向量 collection；入库服务的 `vector_ready` 由实际增量向量写入结果驱动，向量后端失败时保留文本和 KG 检索；GUI 汇总内置与增量状态并保留失败警告；KG 关系只指向用户增量去重后保留的 chunk。检索验证阶段检查当前资料 chunk 是否可作为命中证据、图谱关系引用是否指向有效 chunk，并把 `evidence_chunks`、`evidence_relations`、命中数和异常引用列表写入 `retrieval_verification`。入库、重建和快照导出只修改 `knowledge/runtime`，不修改 `knowledge/csllm`。

知识库维护入口为 `KnowledgeIngestionService.rebuild_indexes()` 和 `KnowledgeIngestionService.export_snapshot(path=None)`。`rebuild_indexes()` 复用用户增量的已解析文档、结构化块和去重 RAG 文本块，重建向量 collection、实体关系、KG 统计、manifest 和最近检索验证状态，不重新解析原始文件，不修改内置数据。`export_snapshot()` 默认写入 `knowledge/runtime/snapshots/knowledge_snapshot_<timestamp>.json`，内容包含用户增量 manifest、文档、结构化块、RAG 文本块、实体、关系和 KG 统计。GUI “知识库”页的“重建索引”和“导出快照”按钮分别调用这两个入口；按钮状态和流水线状态由后台 Worker 更新。GUI 知识图谱画布读取合并后的实体和关系，支持节点/关系搜索、节点类型过滤、关系类型过滤、滚轮缩放、鼠标拖动、节点拖动、节点选中、双击复位和适配图谱；图谱审计面板读取当前可见核心子图和选中节点关系，只影响显示状态，不修改知识库文件。

`format_snippets(task, top_k)` 返回候选生成 LLM 使用的文本片段列表。返回内容包含内置 RAG、用户增量 RAG、向量命中、知识图谱关系和来源清单；文本证据按同一篇文献、同一来源和内容指纹保留最高分命中，图谱证据通过 `S1`、`S2` 这类标签合并引用。

`retrieve(task, top_k, kg_top_k)` 返回结构化任务对应的合并文本块和知识图谱关系，供候选生成和 GUI 证据预览使用。`retrieve_by_query(query, top_k, kg_top_k)` 返回人工工程检索词对应的证据，供 GUI “知识库”页人工核查使用。两类返回值均不直接作为候选结构化参数或工程数值事实源。

## 候选

```json
{
  "candidate_id": "TMP_1",
  "display_name": "TMP_1",
  "source": "DOE",
  "hull_type": "CYLINDRICAL",
  "geometry": {
    "length_mm": 500.0,
    "radius_mm": 100.0,
    "thickness_mm": 10.0,
    "alpha_deg": 40.0,
    "beta_deg": 70.0,
    "imperfection_ratio": 0.008
  },
  "layup": {
    "skin_layup": "[90_4/(±40/±70)_8/90_4]",
    "ply_count": 40
  },
  "material_system": {
    "name": "T700/Epoxy"
  },
  "origin_summary": "| S01 | T700/Epoxy | 500 | 100 | 10 | 40 | 70 | 0.005 | [90_4/(±40/±70)_8/90_4] | 结构稳定性和制造可行性均衡 |",
  "llm_output_excerpt": null
}
```

候选阶段 `candidate_id` 与 `display_name` 均使用 `TMP_N`。`persistent_candidate_id` 不是候选主身份字段；该字段可选，但出现时必须为非空字符串，正常候选生成不写入该字段。

LLM 来源候选经自然语言表格解析后进入结构化校验。`geometry_reference` 不覆盖 LLM 候选参数；`fixed_geometry` 覆盖对应候选参数。材料、长度、半径、厚度、alpha 或 beta 缺失时，LLM 候选不进入候选池；初始几何缺陷比由系统固定为 0.008，LLM 原始提案值保留在来源审计中。案例迁移来源必须来自具备完整设计字段的正式案例。LLM、案例迁移和 DOE 三路候选按材料、几何变量和铺层表达式形成结构等价签名；重复候选不进入候选池，缺口由 DOE 继续补足，最终会话候选重新编号为连续的 `TMP_<n>`。

## 初筛结果

- `surrogate_ultimate_pressure_MPa`：描述符回归估计的承载压力
- `asme_linear_buckling_pressure_MPa`：ASME RD-1172 公式计算的线性屈曲压力，单位 MPa，在 PBIPF 公式中作为 `Q` 输入
- `surrogate_PBIPF_MPa`：与 `surrogate_ultimate_pressure_MPa` 同值的压力代理字段
- `surrogate_prediction_status`：`positive` 表示可参与预筛排名；`nonpositive` 表示公式估计非正，原值保留且不自动送检
- `surrogate_uncertainty_MPa`：已接受案例校准的留一验证 RMSE；没有有效校准记录时为 `null`。这是验证集误差，不是逐候选置信区间，不参与候选排序
- `screening_breakdown.surrogate_detail.PBIPF_descriptors`：计算使用的 `D1`、`D2`、`D3` 工程描述符
- `screening_breakdown.surrogate_detail.PBIPF_imperfection_input`：第三描述符的缺陷输入单位，固定为 `permille`
- `screening_breakdown.surrogate_detail.raw_PBIPF_MPa`：未应用案例比例校准的线性公式原值
- `surrogate_weight`：壳体面密度
- `rank_score`：排序分数；非正预测为 `null`
- `screening_rank`：有效预测中的代理初筛排序；非正预测为 `null`
- `screening_selected`：是否属于当前任务 Top-K 默认有限元送检集合

代理初筛对全部候选计算，有效预测参与排名，不删除非正预测或未入选 Top-K 的候选。GUI 以置灰方式展示未入选候选，人工仍可选择任一候选进入有限元校核。

## 有限元结果

进入有限元前，正式输入沿用候选契约并改为 `candidate_id=C<N>`、`display_name=C<N>`，用 `session_candidate_id=TMP_<N>` 回溯会话候选；正式输入和案例设计不保留重复的 `persistent_candidate_id`。

```json
{
  "candidate_id": "C1",
  "display_name": "C1",
  "session_candidate_id": "TMP_1",
  "status": "success",
  "retry_count": 0,
  "ultimate_pressure_MPa": 32.5,
  "failure_pressure_MPa": 32.5,
  "linear_buckling_pressure_MPa": 35.1,
  "first_mode_eigenvalue": 35.1,
  "postbuckling_reference_pressure_MPa": 30.0,
  "riks_lpf_max": 1.0833,
  "imperfection_amplitude_mm": 0.525,
  "ultimate_pressure_basis": "一阶屈曲模态缺陷 Static Riks 最大 LPF × 基准外压",
  "failure_mode": "非线性后屈曲极限点",
  "weight_kg_per_m2": 15.5,
  "visualization_json": "data/abaqus_runs/C1/C1_mode1.json",
  "linear_buckling_odb": "data/abaqus_runs/C1/C1.odb",
  "postbuckling_odb": "data/abaqus_runs/C1/C1_post.odb",
  "verdict": "通过"
}
```

报告产物仅为 `overall_design_report.md/pdf`，两种格式对应一份总体设计方案报告。输入 `candidates` 为完整候选池，含生成依据和预筛排名；`results` 仅包含实际有限元返回值。输出 `report_kind=overall`、`report_outputs={overall: artifact}`，不写其他分报告或汇总副本。GUI 可指定保存目录，未校核候选不进入有限元结论统计。极限点、渐进损伤证据或目标比较数据不足时不作最终推荐。工艺原因读取实际生成记录，工艺建议不视为已验证工艺。

`visualization_json` 是 GUI 云图显示输入，不作为有限元数值结论来源。GUI 初始显示等待提示；候选生成后优先使用 `pyvistaqt` 交互显示候选三维几何，有限元校核完成后可切换显示一阶模态云图，支持旋转、缩放、平移和双击复位。交互式 OpenGL 视图不可用或处于 GUI 渲染检查环境时，使用与当前主题一致的 Matplotlib 静态工程预览显示候选几何或模态云图。离线图注跟随界面语言，并在详情页展示模态数据文件路径、点数、面数、标量数量和可用性状态。

初始几何缺陷比采用 `analysis_assumptions.imperfection_ratio=0.008`（8‰）。模型提案值保存在 `provenance.proposed_imperfection_ratio`，不直接作为预筛或求解输入；未提供提案值时该审计字段为 `null`。LLM、案例迁移和 DOE 的实际候选使用同一配置值。历史已求解案例保留原始参数，不重写数值证据。

正式求解入口在分配编号前检查固定缺陷条件；外部候选不符合条件时明确拒绝，不静默改写参数。`FEMAgent` 返回的 `solved_design` 保存实际求解的几何、铺层、材料、载荷、边界、分析参数和设计修订号。自动重试产生设计修订时，案例回流读取该设计，报告使用实际求解尺寸比较厚度或壳体质量；缺少实际尺寸证据的重试结果不参与对应目标的推荐。报告仍保留初始候选池及其生成理由，不把修订方案伪装为初始方案。

## 知识回流结果

状态图节点 `persist_knowledge` 接收 `task`、`fem_designs` 和 `results`，输出 `knowledge_updates`。`fem_designs` 保存已经晋级为正式编号的有限元输入，`results` 保存对应有限元结果。知识回流不调用 LLM，不修改有限元结果。

```json
{
  "status": "stored",
  "case_id": "CASE_1",
  "candidate_id": "C1",
  "session_candidate_id": "TMP_1",
  "retrained": false,
  "surrogate_summary": null
}
```

证据不完整时，`status` 为 `not_stored_incomplete`、`case_id` 为 `null`，`reason` 列出缺失证据，不消耗案例号。重复回流同一设计与结果返回已有案例号和 `already_stored: true`。回流异常时，`status` 为 `failed` 或 `missing_result`，并包含 `error`；诊断进入运行审计，不改变 Abaqus 数值。

## 运行审计报告

监控页的运行审计入口调用 `workflow/run_audit.py`，读取当前 `run_id` 对应的工作流快照、事件审计和有限元作业队列，生成 Markdown 文件：

```text
data/results/run_audit_<RUN_ID>.md
```

运行审计报告包含以下内容：

- 运行摘要：阶段、人工确认点、任务、载荷、边界、候选数量、初筛数量、有限元结果数量、知识回流数量和报告路径。
- 智能体职责契约：状态图节点、运行时智能体、工具、LLM 边界和失败策略。
- 候选-结果-案例追踪：TMP 会话候选、正式 C 编号、代理预测、FEM 极限压力、代理误差、CASE 编号和回流状态。
- 有限元队列：作业编号、TMP 编号、C 编号、状态、结果摘要和错误摘要。
- LLM 调用轨迹：用途、选用后端、选用模型、是否回退和每次尝试状态。
- 诊断与事件审计：节点失败、工具失败、有限元失败、快照错误和完整事件列表。

运行审计报告只读取已经落盘的运行事实，不重新触发 LLM、代理模型、有限元或知识回流，不参与候选排序、案例编号或报告正文生成。

工具调用事件由 `workflow/tool_registry.py` 写入 `workflow_events`。`tool_started` 包含 `tool`、`description`、`input_schema`、`output_schema` 和 `input_summary`；`tool_completed` 额外包含 `duration_ms` 和 `output_summary`；`tool_failed` 包含 `duration_ms`、`input_summary` 和 `error`。`input_summary` 与 `output_summary` 只保存列表数量、关键字段和短文本截断，不保存报告全文、长正文、URL 密钥或提示词正文。

## 案例记录

完整案例保存在 `data/cases`，通过设计校核的完整样本同步进入 `knowledge/case_library` 和案例记忆索引。`CASE_N` 按入库顺序连续分配，不要求与正式求解号 `C<N>` 同号。顶层 `candidate_id`、`display_name` 与设计和结果中的求解号一致。会话案例直接保存 `run_id`、`task_id` 和 `session_candidate_id`；`TMP_N` 只在所属会话内有效，预筛不重新编号。结果匹配必须核对求解号、会话号和会话候选号，不能仅按 `TMP_N` 关联。

默认会话报告保存到 `data/results/<RUN_ID>/`，快照中的报告路径指向该目录，其他会话不能覆盖这些文件。用户明确选择导出目录时使用指定目录；同一目录中同名导出文件由用户负责区分。
