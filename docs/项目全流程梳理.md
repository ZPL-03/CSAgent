# 项目全流程梳理

## 项目定位

CSAgent 多智能体智能设计平台面向复合材料外压圆柱耐压壳设计。系统以多智能体编排为主线，把自然语言需求转为结构化设计任务，生成候选方案，完成代理模型初筛，执行真实 ABAQUS 有限元校核，写入案例库并导出设计报告。

运行事实源位于本项目目录内。模型接口、知识库、案例数据、公式系数、材料库和任务契约均读取本项目文件。

产品显示名为 `CSAgent 多智能体智能设计平台`。`CSDM_cph` 只作为本地目录、Python 包和环境变量前缀保留；界面、报告、运行记录和交付展示统一使用 CSAgent。

## 运行环境

- Conda 环境：`AGENT`
- Windows 解释器：`D:\anaconda3\envs\AGENT\python.exe`
- GUI 入口：`main.py`
- 环境自检：`scripts/check_env.py`
- 主模型配置：项目根目录 `.env` 中的 `LLM_PRIMARY_URL`、`LLM_PRIMARY_API_KEY`、`LLM_PRIMARY_MODEL_NAME`
- 回退模型配置：项目根目录 `.env` 中的 `URL`、`API_KEY`、`MODEL_NAME`
- 工作站领域模型接口示例：`LLM_PRIMARY_URL=https://csllm.ipen03.com/v1`，`LLM_PRIMARY_MODEL_NAME=csllm`

所有脚本、GUI、测试和环境检查均使用 `AGENT` 环境。

## 多智能体运行时

当前工程化运行时位于 `workflow/`。主对话流程通过 LangGraph 状态图推进，同时保留 PyQt6 手动调试入口。运行时状态包含任务、候选池、初筛结果、正式有限元输入、有限元结果、知识回流结果、报告、人工确认状态和错误信息。

| 节点 | 运行智能体 | 对应职责 | 工具 |
| --- | --- | --- | --- |
| `parse_task` | `ORCHESTRATOR` | 需求解析与任务契约生成；这是编排智能体的确定性入口阶段，不是独立智能体 | `parse_task` |
| `generate_candidates` | `CANDIDATE_GEN` | LLM、案例迁移和 DOE 候选池生成 | `generate_candidates` |
| `screen_candidates` | `SCREENER` | ASME RD-1172 与 PBIPF 初筛 | `screen_candidates` |
| `evaluate_candidates` | `FEM_AGENT` | Abaqus 有限元校核 | `evaluate_candidates` |
| `persist_knowledge` | `KNOWLEDGE_AGENT` | 案例库、案例记忆和代理公式校准数据回流 | `persist_knowledge` |
| `generate_report` | `REPORT_GEN` | 设计报告导出 | `generate_report` |
| `wait_screen`、`wait_fem`、`wait_report` | `ORCHESTRATOR` | 人工确认节点 | 工作流状态 |

`workflow/event_store.py` 使用 SQLite 保存 `workflow_runs`、`workflow_events` 和 `workflow_snapshots`。每个节点启动、完成、失败、工具调用和人工确认都会写入事件表。`workflow/tool_registry.py` 在工具事件中记录工具名、运行智能体、输入摘要、输出摘要、耗时和失败原因；输入输出摘要只保留规模与关键字段，不保存大段正文、报告全文或密钥。`workflow/simulation_queue.py` 在同一运行库中保存 `simulation_jobs`，记录有限元作业从入队到完成或失败的状态、候选编号、正式编号、结果摘要和错误信息。工作流可通过 `run_id` 读取最近快照并从等待确认节点继续执行。GUI“监控”页提供最近运行记录下拉框、刷新运行记录和恢复运行状态入口；恢复运行状态只读取本地持久化快照，不重新触发 LLM、代理模型或 Abaqus。运行库位于 `data/runtime/`，属于本地运行产物，不进入 Git。运行时低层事件实时回传 GUI，写入工作台运行日志和监控日志；聊天区只承载高层协作消息、确认请求和人工输入。

`workflow_runs.status` 由最新快照统一推导：等待人工确认节点为 `waiting`，用户驳回并暂停为 `paused`，节点异常为 `failed`，完整结束为 `completed`，其余阶段为 `running`。运行列表、监控页和审计报告读取同一状态字段，确保恢复、诊断和状态灯展示口径一致。

`workflow/agent_contracts.py` 定义运行时智能体职责契约。每个契约包含状态图节点、运行时智能体名、工具名、实现模块、职责、输入契约、输出契约、LLM 调用边界、记忆策略、事件策略和失败策略。`parse_task` 是 `ORCHESTRATOR` 的确定性解析阶段，用于审计和恢复，不作为第七个智能体展示。`workflow/runtime.py` 注册工具时读取同一份契约，GUI 也读取同一份契约展示，避免状态图、工具审计和界面描述分叉。

GUI 当前为四页导航：工作台、知识库、监控和设置。工作台读取同一运行库，展示 LangGraph DAG、候选池、来源审计、多智能体对话、人工确认、实时视口、会话指标、运行日志、阶段报告入口和数据导出入口。工作台候选池展示全部会话候选、来源审计、代理预测、初筛排名和选中状态；代理初筛后全量候选按评分排序，Top-K 标记为默认送检集合，未入选候选置灰但仍可人工送入有限元校核。候选详情展示 TMP 会话候选、正式 C 编号、代理预测、FEM 结果、代理误差、CASE 回流状态和报告纳入状态之间的对应关系；该追踪信息只做展示，不参与排序、校核或回流写入。阶段报告区读取当前会话报告或 `data/results/latest_report.md`，展示 Markdown/PDF 路径、LLM 工程解释使用状态和 Markdown 正文预览。右侧实时结果区提供会话数据导出入口，输出 `data/results/session_export_<RUN_ID>.json` 和 `data/results/session_trace_<RUN_ID>.csv`，用于离线复核任务快照、候选来源、代理预测、FEM 结果和 CASE 回流关系。监控页展示正式案例指标、Pareto 前沿、最佳极限压力收敛历史、状态恢复、运行审计、工具调用审计、LLM 调用轨迹、有限元队列和诊断信息，并可导出单次运行审计报告；运行审计报告写入 `data/results/run_audit_<RUN_ID>.md`。

PyQt6 主界面默认为简体中文，“设置”页支持 English、跟随系统、深色工程和亮色工程。界面偏好写入 `data/runtime/ui_settings.json`，属于本地运行状态。主程序启动时优先使用 Segoe UI 显示英文、数字和符号，中文回退到 Microsoft YaHei UI、Microsoft YaHei、Noto Sans SC，代码和日志使用 Cascadia Mono。界面采用 `QMainWindow + QSplitter + QStackedWidget` 工程工作台布局：顶部为 CSAgent 标识、页面导航和当前模型标识；左栏展示六个运行时智能体状态、任务队列和知识连接；中央 Stack 包含工作台、知识库、监控、设置；工作台中部上方为自绘 LangGraph DAG，知识智能体作为 `ORCHESTRATOR → CANDIDATE_GEN` 之间的检索/上下文注入支线显示；工作台中部下方为对话优先交互区；右栏展示实时视口、会话指标、运行日志、阶段报告、会话数据导出和报告打开入口。知识库页展示资料入库状态、五阶段流水线、文档表、混合检索结果、证据关系、可搜索/拖动/缩放/复位的核心知识图谱和节点审计面板；图谱节点颜色区分实体类型，节点大小反映度数和计数，选中节点后审计面板展示类型、度数、计数和可见关联关系。监控页读取正式案例库 FEM 指标，绘制结构面密度与极限压力 Pareto 前沿、最佳极限压力收敛历史、最佳案例指标和正式案例数量，并保留工作流审计、运行日志和状态恢复入口。设置页提供主/回退 LLM、Abaqus、候选来源比例、人工确认节点、RAG/KG 分块和向量索引等本地 YAML 配置表单；右栏展示主模型、回退模型、Abaqus、RAG/KG、候选来源比例和人工确认节点的配置健康状态；密钥仍由 `.env` 管理，GUI 不显示密钥正文。实时视口在本机 OpenGL 可用时使用 PyVista 交互视图，支持旋转、缩放、平移、双击重置、按钮重置视角和适配窗口；交互式 OpenGL 不可用或处于离线审计环境时，使用与当前主题一致的 Matplotlib 静态工程预览显示参考几何、候选几何或一阶模态云图。DAG 和左侧智能体卡片使用完成、运行中、失败、等待四类状态灯，后台动作失败时会话阶段进入 `failed` 并刷新对应智能体状态。GUI 层只负责展示、触发和恢复流程，不改变任务契约、候选契约、代理公式、有限元输入输出或案例编号规则。

## LLM 职责边界

主模型是领域微调模型 `csllm`。该接口用于领域候选提案和报告工程解释，不作为流程控制或工程数值事实源。候选生成 LLM 会读取合并 RAG/KG 检索片段，用于补充工程提案依据；候选结构化参数仍由系统解析、归一化、规则检查和 Schema 校验确定。

LLM 后端使用主模型优先、回退模型补充的调用顺序。主模型不可连接、返回空文本或请求异常时，`LLMBackend` 按配置继续尝试回退模型；候选生成和报告解释智能体把最近一次调用链路写入 `llm_call_trace` 事件。调用轨迹包含后端名称、模型名称、调用状态、耗时、返回字符数和错误摘要，不包含 URL、密钥、系统提示词或用户提示词。GUI 顶部当前模型标识根据该事件显示实际使用的领域主模型、回退模型或失败状态，并同步写入工作台运行日志和监控日志。监控页读取调用轨迹，展示选用后端、是否发生回退和每次尝试结果。健康检查由本地审计脚本或人工动作触发，不在 GUI 启动时自动联网；输出只包含后端名称、模型、检测状态、耗时和脱敏错误摘要。

| 模块 | LLM 职责 |
| --- | --- |
| `TaskParser` | 不调用 LLM；候选池数量、Top-K、载荷、几何、目标压力由规则解析得到 |
| `CandidateGenAgent` | 生成 LLM 来源候选提案；输入为系统整理后的工程任务书，包含用户已给事实、合并 RAG/KG 检索片段、LLM 候选数量、输出字段要求和系统候选字段约束；输出为自然语言候选表，由系统解析为结构化候选 |
| `ReportGenAgent` | 任务事实、候选编号、数值和有限元结论由结构化数据确定性生成；工程解释与制造建议可调用 LLM 做定性解释，约束清理后仍异常时退回确定性解释 |
| `ScreenerAgent` | 不调用 LLM |
| `FEMAgent` | 不调用 LLM |
| `KnowledgeAgent` | 不调用 LLM |
| `ConversationFlowController` | 不调用 LLM，进度说明由确定性模板生成 |

## GUI 输入与任务控制

GUI 核心工作台底部只输入自然语言设计需求。需求中必须明确给出候选池总数和初筛保留数量，例如“生成 12 个候选，初筛保留 5 个候选”。任一数量缺失时，系统不启动主流程。

候选池数量和初筛保留数量是任务参数，不是固定值。系统按当前任务的 `total_candidates` 和 `top_k_candidates` 执行。

候选来源使用默认初始比例 `LLM:案例迁移:DOE = 2:1:1`。该比例只用于计算三条来源的初始目标配额，例如候选池总数为 12 时，初始配额为 LLM 6 个、案例迁移 3 个、DOE 3 个。实际候选来源统计以规则检查后的有效输出为准；当领域主模型合规输出不足或正式案例库中可迁移案例少于初始配额时，实际来源拆分会变化，候选池总数由 DOE 参数采样完成数量闭合。

任务解析会额外生成 `user_input_facts`。该字段只记录用户自然语言明确给出的事实，包括候选池总数、初筛保留数、外压、边界、材料、目标压力和用户明确给出的几何条件。长度、半径、厚度、铺层角或缺陷比默认进入 `fixed_geometry`，作为候选生成和有限元输入必须满足的条件；只有字段附近出现“约、参考、附近、设计中心、左右”等参考语义时，对应字段才进入 `geometry_reference`，作为设计中心和几何包络依据。系统内部为规则检查、DOE、候选变量完整性和有限元准备的工程域参数不写入 `user_input_facts`，也不作为用户事实发送给候选生成 LLM。

## 全流程

### 1. 启动与目录准备

`main.py` 调用 `ensure_project_dirs()` 确保 `data/`、`knowledge/`、`models/`、`docs/` 和 ABAQUS 运行目录存在，然后启动 PyQt6 主界面。

### 2. 任务解析

`ConversationFlowController.start()` 接收 GUI 输入，调用 `OrchestratorAgent.parse_instruction()`。`TaskParser` 执行规则解析，不调用领域主模型。规则解析得到以下字段：

- 外部静水压力
- 边界条件
- 长度、半径、厚度、铺层角、缺陷比参考值或固定约束
- 极限压力目标
- 候选池总数
- 初筛保留数

GUI 与编排器主流程会将解析结果写入 `data/tasks/TASK_N.json`，编号按现有任务文件顺延。`task_id` 是会话追溯字段，不是案例主身份字段；历史导入、批量建库和底层脚本生成案例时，如果没有真实任务来源，案例记录不写入 `task_id`。

`TaskParser` 使用规则解析生成任务契约。内部工程默认值只用于任务契约完整性、DOE 参数域、规则检查、候选变量完整性和有限元接口，不进入 `user_input_facts`。明确几何数值形成 `fixed_geometry` 和固定范围；参考几何数值形成 `geometry_reference` 和局部几何包络，用于引导候选靠近用户关心的尺度。候选生成 LLM 读取 `user_input_facts`、项目知识库/知识图谱片段和 LLM 目标候选数；提示词要求模型把非固定几何写成候选建议值，而不是用户已给固定条件。

### 3. 候选方案生成

`CandidateGenAgent` 组织三类来源：

| 来源 | 作用 |
| --- | --- |
| `LLM` | 基于用户已给事实生成自然语言候选方案表 |
| `CASE_TRANSFER` | 从正式案例库检索相近通过案例并绑定当前任务约束 |
| `DOE` | 在参数范围内进行确定性采样，提供参数空间覆盖 |

三路来源均属于候选池组成部分。初始目标配额按 `config/app_config.yaml` 中的 `pipeline.candidate_source_ratio` 计算。实际进入候选池的数量以有效候选为准：

- LLM 输入不是原始用户自然语言，而是系统整理后的工程任务书：任务书写明需要生成多少套 LLM 来源候选，列出 `user_input_facts` 中的用户已给信息、输出字段要求和系统候选字段约束。
- 系统候选字段约束只描述项目材料库、参数域、单位和可解析铺层格式，用于防止模型输出无法校核的候选；这些约束不进入 `user_input_facts`，也不能被模型叙述为用户已给事实。
- 项目知识库/知识图谱片段只作为 LLM 工程提案依据，不作为用户已给事实，不直接写入结构化候选。
- LLM 输出保持训练数据中的自然语言工程回答风格，通常包含候选方案表、筛选逻辑和制造/FEM 建议。候选表中的推荐理由需要同时说明结构性能依据和制造/缺陷风险依据。系统从自然语言表格或编号方案中提取材料、长度、半径、厚度、alpha、beta、缺陷比和铺层表达式；候选编号列不参与材料解析。
- LLM 输出的候选行保存到 `origin_summary`，回答原文保存到 `llm_output_excerpt`，用于 GUI 查看和候选来源追踪。
- LLM 候选的材料、长度、半径、厚度、alpha、beta、缺陷比必须在结构化候选中完整存在。`geometry_reference` 不会覆盖 LLM 候选参数；`fixed_geometry` 会覆盖对应候选参数并形成固定几何约束。
- LLM 候选缺少材料、长度、半径、厚度、alpha、beta 或缺陷比时不进入候选池，系统不使用通用默认几何或材料库补齐这些主设计字段。
- LLM、案例迁移和 DOE 三路候选按材料、几何变量和铺层表达式形成结构等价签名；签名重复的候选不进入候选池，候选池缺口由 DOE 继续补足。
- 案例迁移只使用正式案例库中通过有限元校核、工况边界匹配、材料兼容的真实案例。
- 案例迁移不把同一条案例复制成多个迁移候选；可迁移案例少于初始配额时，实际案例迁移数量随之减少；案例设计缺少必要几何字段时直接跳过，不使用默认几何补齐。
- DOE 按参数域采样承担参数空间覆盖，并在 LLM 或案例迁移有效数量不足时完成候选池数量闭合。

候选生成结束时写入 `generation_audit`。该审计记录三路初始配额、原始输出数、规则有效数、实际进入候选池数量、规则过滤数量、结构去重数量、DOE 补足数量、DOE 采样轮次和过滤原因摘要。审计随候选池进入 GUI，并通过 `candidate_generation_audit` 事件写入工作流事件库；工作台候选池在摘要和候选详情中展示该审计。

每个候选都会执行：

- 几何范围归一化
- 铺层格式归一化
- 铺层模板修复
- 材料体系绑定
- 规则检查
- JSON Schema 校验

候选会话编号使用 `TMP_N`，候选阶段的 `candidate_id` 与 `display_name` 都写为该会话编号，不写空的 `persistent_candidate_id`。进入有限元前，正式候选编号使用 `C_N`，按已有案例编号顺延；正式输入的 `candidate_id` 与 `display_name` 都写为正式编号，并通过 `session_candidate_id=TMP_N` 回溯会话候选。有限元结果落盘后同步保留 `session_candidate_id`，后续报告和案例追溯不依赖 GUI 内存态。

### 4. 代理模型初筛

`ScreenerAgent` 对候选池逐个计算代理结果。该阶段不调用 LLM。

ASME RD-1172 线性屈曲压力由 `core/pressure_hull_profile.py` 计算，字段为 `asme_linear_buckling_pressure_MPa`，在 PBIPF 公式中记为 `Q`。

极限压力使用 PBIPF 公式：

```text
P_PBIPF = d1 * lg(Q) * t / R
        + d2 * Q * D22 / (D33 - D12)
        + d3 * Q * Ir * L / A22
        + d0
```

排序分数为：

```text
score = pressure_weight * P_ult
      - weight_penalty * 面密度
      - uncertainty_penalty * 公式不确定度
```

初筛保留数量使用当前任务的 `top_k_candidates`，并受候选池实际数量上限约束。初筛不会删除候选池中的其他方案；排序后的全量候选继续进入 GUI，Top-K 是默认有限元送检集合，非 Top-K 候选保留人工送检入口。

### 5. 有限元校核

`FEMAgent` 将入选候选转为 ABAQUS 输入，执行真实有限元校核。该阶段不调用 LLM。候选进入有限元前由运行时晋级为正式 `C_N` 编号，并在 `fem_designs` 中保留正式输入；有限元结果继续保留 `session_candidate_id` 回溯会话候选。

有限元包含两个阶段：

1. 单位外压线性屈曲分析，输出一阶线性屈曲压力和一阶模态云图数据。
2. 以一阶模态作为几何缺陷进入 Static Riks 后屈曲分析，极限压力取最大 LPF 与基准外压的乘积。

结果字段包括：

- `linear_buckling_pressure_MPa`
- `ultimate_pressure_MPa`
- `riks_lpf_max`
- `imperfection_amplitude_mm`
- `visualization_json`
- `linear_buckling_odb`
- `postbuckling_odb`
- `verdict`

GUI 的工作台候选池、右侧实时视口和监控页 FEM 指标区读取候选几何、有限元结果和 `visualization_json`。交互环境可用时，右侧实时视口使用 `pyvistaqt` 显示可旋转、缩放、平移的三维候选几何和一阶模态云图，并支持双击复位视角；无候选或结果时显示参考耐压壳交互模型。交互式 OpenGL 视图不可用、`pyvistaqt` 初始化失败、`QT_QPA_PLATFORM=offscreen`、`CSDM_cph_DISABLE_INTERACTIVE_3D=1` 或需要离线审计时，界面使用与当前主题一致的 Matplotlib 静态工程预览显示参考几何、候选几何或一阶模态云图。结果详情展示模态数据文件路径、点数、面数、标量数量和可用性状态，便于判断云图缺失是求解未产出、路径不存在还是数据不完整。

未找到 ABAQUS 命令或求解失败时返回诊断结果，不生成虚假通过结果。

### 6. 案例与知识回流

`KnowledgeAgent` 由状态图节点 `persist_knowledge` 独立调用，写入案例记录。该阶段不调用 LLM。

案例编号使用 `CASE_N`，与正式候选编号 `C_N` 对应。通过校核的案例进入 `knowledge/case_library` 和案例记忆索引；未通过或求解失败的案例只进入评估档案。案例记录有真实会话来源时保留 `task_id`，没有真实会话来源时不写该字段。知识回流结果写入工作流快照字段 `knowledge_updates`，并通过 `KNOWLEDGE_AGENT` 工具事件审计。单个案例回流失败时写入失败摘要和诊断事件，不修改有限元结果本身。

案例记录顶层保存正式 `candidate_id` 与 `display_name`，并与 `design.candidate_id`、`design.display_name` 保持一致。案例设计保存正式 `candidate_id`、正式 `display_name` 和可用的 `session_candidate_id`，不保存重复的 `persistent_candidate_id`。案例记录包含：

- 结构化任务
- 设计参数
- 代理模型初筛字段
- 有限元结果
- 代理预测误差
- 结论与诊断说明

### 7. 报告输出

`ReportGenAgent` 汇总任务、候选池、初筛理由、有限元结果和工程建议，按报告类型输出：

- `recommended_design_solution.md/pdf`：推荐设计方案，读取候选生成、来源审计、代理初筛排序和推荐理由。
- `fem_verification_report.md/pdf`：有限元校核报告，读取正式 C 编号、两阶段有限元结果、云图路径、诊断摘要和通过结论。
- `overall_design_report.md/pdf`：总体设计报告，读取任务契约、候选池、初筛、有限元、知识回流和工程解释。
- `latest_report.md/pdf`：最近一次报告导出的兼容入口。

GUI 阶段报告区提供报告类型选择和保存目录选择。推荐设计方案可在候选池和代理初筛完成后导出；有限元校核报告和总体设计报告需要已有有限元结果。报告生成智能体只读取当前会话结构化数据、当前候选池和已经完成的有限元结果，不用 LLM 编造缺失数值。

GUI 会话数据导出入口输出：

- `data/results/session_export_<RUN_ID>.json`
- `data/results/session_trace_<RUN_ID>.csv`

`session_export_<RUN_ID>.json` 保存当前会话的任务、候选池、初筛结果、有限元结果、知识回流结果和报告元数据。`session_trace_<RUN_ID>.csv` 保存 TMP 会话候选、正式 C 编号、CASE 编号、候选来源、代理预测、FEM 结果、结论和知识回流状态之间的扁平追踪表。

任务事实、外压、目标压力、候选编号、代理模型初筛字段和有限元结论由结构化数据直接写入。工程解释与制造建议段可调用 LLM，输入只包含结构化任务、候选池、入选候选和有限元结果，提示词要求定性解释铺层、制造工艺、缺陷控制和验证建议。LLM 输出出现结构化输入之外的新数值、阈值或材料牌号时先做约束清理；清理后仍不合规或调用失败时，报告使用确定性工程解释。

报告导出面向已有有限元校核结果，可作为阶段报告使用；未校核候选仍保留在当前候选集中，不进入有限元结果章节和结论统计。

GUI 报告预览不修改报告内容，不调用 LLM，只显示 `ReportGenAgent` 已生成的 Markdown 内容或最新落盘报告文件。

## 知识库与知识图谱

知识库读取本项目内置 RAG/KG 数据和用户上传增量数据。`knowledge/csllm` 保存内置数据，`knowledge/runtime` 保存用户增量，`DomainKnowledgeBase` 对外提供合并后的总 RAG/KG 检索入口：

- 内置 RAG 文本块：`knowledge/csllm/rag/rag_chunks.compact.jsonl.gz`
- 内置知识图谱实体：`knowledge/csllm/kg/entities.jsonl`
- 内置知识图谱关系：`knowledge/csllm/kg/relations.compact.jsonl.gz`
- 内置数据清单：`knowledge/csllm/provenance/manifest.json`
- 用户上传原始资料：`knowledge/runtime/uploads/`
- 用户增量结构化文档：`knowledge/runtime/structured_text/documents.jsonl`
- 用户增量结构化文本块：`knowledge/runtime/structured_text/blocks.jsonl`
- 用户增量 Markdown 全文：`knowledge/runtime/structured_text/markdown_documents/`
- 用户增量 RAG 文本块：`knowledge/runtime/rag/rag_chunks.jsonl`
- 向量索引：`knowledge/chroma_db` 中的 `csdm_cph_project_knowledge` collection
- 用户增量知识图谱实体：`knowledge/runtime/kg/entities.jsonl`
- 用户增量知识图谱关系：`knowledge/runtime/kg/relations.jsonl`
- 用户增量状态：`knowledge/runtime/manifest.json`

用户在 GUI “知识库”页上传资料或批量选择资料后，`KnowledgeIngestionService` 将资料复制到 `uploads/` 并计算文件 SHA256。文档编号使用 `DOC_<sha256前12位>`，同一资料重复入库会替换同一文档记录，不生成虚假新编号。PDF、DOCX、PPTX 和图片优先调用 MinerU，失败后尝试 Docling；PDF 文本层充足时使用 MinerU pipeline 文本路由，文本层稀疏或扫描型资料使用 MinerU high-accuracy 路由；外部解析器不可用时，PDF 继续使用 PyMuPDF 尝试文本层解析，DOCX、PPTX 继续尝试文本层解析，图片保留图片元数据。文本、Markdown、JSON/YAML/TOML/INI、CSV、TSV、XLSX/XLSM、Abaqus 输入、子程序、日志、状态和消息文件由本项目解析器转换为 Markdown。ODB、SIM、CAE 等工程二进制文件进入可检索元数据索引，内部场变量和云图仍由有限元结果可视化链路读取。GUI 文件选择器使用 `core.knowledge_ingestion.SUPPORTED_QT_FILE_FILTER`，与核心解析器支持类型保持同源。入库服务在文档解析、语义分块、向量化索引、实体/关系抽取和检索验证 / 证据引用阶段发出进度事件；后台 Worker 将事件转发给 GUI，知识库页的流水线卡片按真实阶段实时显示运行、成功、警告和失败状态。

解析后的 Markdown 进入结构化文本块生成。RAG 分块使用 `config/app_config.yaml` 中的 `chunk_token_size`、`chunk_overlap_tokens` 和 `min_chunk_tokens`；token 计数优先使用 `tiktoken`，不可用时使用中英文混合估算。完全相同的 RAG 文本块按 `content_hash` 去重；去重后的用户增量 chunk 写入 JSONL 文本索引，并同步写入 ChromaDB 项目知识 collection。向量索引默认使用 `rag.embedding_model=BAAI/bge-m3` 和本地缓存；`vector_ready` 只在实际 collection 写入成功且写入数量大于 0 时为真。向量后端不可用时保留 JSONL/BM25 和 KG 检索，manifest 写入 `vector_status=warning`、`vector_backend=unavailable` 和失败摘要，GUI 以黄色状态灯显示。KG 使用领域词典抽取材料、结构、失效模式、制造工艺、公式和验证方法实体，写出用户增量 `entities.jsonl`、`relations.jsonl` 和 `kg_stats.json`。新资料入库时，已有上传资料的 RAG 文本块、实体和关系继续保留；同一资料重复入库时按文档编号替换该资料旧记录，避免重复堆积，不修改内置数据。检索验证阶段会构造当前资料的工程检索词，检查当前资料 chunk 能进入命中结果、图谱关系的 `evidence_chunk_id` 指向去重后有效 chunk，并把 `retrieval_verification`、证据 chunk 样本和关系样本写入 manifest。尚未上传任何资料时，知识服务仍读取内置 RAG/KG，并返回用户增量区完整状态契约：0 文档、0 chunk、0 实体关系、分块 token、overlap、`content_hash` 去重字段、向量状态字段和五阶段 pending 流水线。

GUI 的“知识库”页提供索引重建入口。索引重建只读取用户增量的已解析文档、结构化块、去重 RAG 文本块和当前 KG 记录，重建 Chroma 向量 collection、实体关系、KG 统计、manifest 和最近检索验证状态，不重新解析原始文件，不修改内置数据。快照导出入口写入 `knowledge/runtime/snapshots/knowledge_snapshot_<timestamp>.json`，内容包含用户增量 manifest、文档、结构化块、RAG 文本块、实体、关系和 KG 统计。

候选生成 LLM 接收用户已给事实、LLM 候选数量、输出字段要求和合并 RAG/KG 检索片段。`DomainKnowledgeBase` 对同一查询融合内置 JSONL/BM25、用户增量 JSONL/BM25、Chroma 向量 collection 和 KG 关系，按来源去重后返回证据和来源清单。证据用于 LLM 工程提案、制造解释和人工核查，不替代 ASME RD-1172、PBIPF、代理模型排序或 Abaqus 校核。GUI 的“知识库”页展示状态灯、入库流水线、资料表、合并知识图谱、人工检索和证据预览；启动和重置时只刷新状态，不自动执行完整检索。知识图谱画布读取合并后的实体和关系，用节点颜色区分材料、结构、失效模式、公式、验证方法和制造工艺，并高亮当前检索命中的关系；画布支持节点/关系搜索、节点类型过滤、关系类型过滤、滚轮缩放、鼠标拖动、节点拖动、节点选中、双击复位和适配图谱。图谱审计面板显示总实体、总关系、可见核心子图规模、节点类型分布、关系类型分布和选中节点关联关系。

## 编号规则

| 对象 | 编号 | 位置 |
| --- | --- | --- |
| 任务追溯 | `TASK_N` | `data/tasks`，仅 GUI 与编排器主流程产生真实会话任务时写入 |
| 会话候选 | `TMP_N` | 内存与 GUI 表格 |
| 正式候选 | `C_N` | 有限元输入与结果 |
| 案例 | `CASE_N` | `data/cases`、`knowledge/case_library` |

正式候选和案例编号均按已有文件最大编号顺延。会话候选仅使用 `TMP_N`，不占用正式候选和案例编号。会话候选显示名等于 `TMP_N`，正式有限元输入、案例记录顶层和案例设计显示名等于 `C_N`。案例编号、案例迁移检索和案例记忆索引不依赖 `task_id`；案例契约保留 `task_id` 属性，但不要求每条案例都包含该字段。
