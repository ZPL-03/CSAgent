# CSAgent 项目状态

## 当前事实

- 项目目标为复合材料外压圆柱耐压壳智能设计。
- 主流程为耐压壳多智能体智能设计编排。
- LLM 配置读取项目根目录 `.env`，主模型使用 `LLM_PRIMARY_URL`、`LLM_PRIMARY_API_KEY`、`LLM_PRIMARY_MODEL_NAME`，回退模型使用 `URL`、`API_KEY`、`MODEL_NAME`。
- LLM 后端按主模型优先、回退模型补充的顺序调用；候选生成和报告解释会记录 `llm_call_trace` 事件，事件只包含后端名称、模型名称、状态、耗时、返回字符数和错误摘要，不包含 URL、密钥或提示词正文。
- GUI “智能体流程”页提供“检测 LLM 后端”和“导出运行审计”按钮；LLM 健康检查由人工触发，检测结果不展示 URL、密钥或提示词正文；运行审计报告写入 `data/results/run_audit_<RUN_ID>.md`。
- PyQt6 主界面默认为简体中文，顶部语言选择器支持 English，主题选择器支持跟随系统、深色工程和亮色工程；界面偏好写入 `data/runtime/ui_settings.json`，不进入 Git。主程序启动时优先加载 `HarmonyOS Sans SC`、`Noto Sans SC` 和 Windows 中文字体，避免中文控件和可视化图注显示为方块。
- PyQt6 主界面采用 `QMainWindow + QSplitter + QStackedWidget` 工程工作台布局：顶部为系统身份栏、页面导航和当前模型标识；语言和主题选择位于“设置”页；左栏展示六个智能体状态、任务队列和知识连接；中央 Stack 包含工作台、项目、知识库、监控、设置；工作台中部上方为自绘 LangGraph DAG，下方为对话优先交互区；右栏展示实时视口、会话指标、运行日志、阶段报告和报告打开入口。
- 工作站领域模型接口示例为 `LLM_PRIMARY_URL=https://csllm.ipen03.com/v1` 和 `LLM_PRIMARY_MODEL_NAME=csllm`。
- GUI 主流程只使用自然语言设计需求，需求中必须明确包含候选池总数和初筛保留数。
- PyQt6 主界面包含“任务配置”页，展示结构化任务契约、用户已给事实、普通几何参考、固定几何约束、候选生成控制参数、初筛控制参数和事实边界；该页只读取当前会话任务，不修改任务、候选或流程状态。
- LLM、案例迁移和 DOE 的初始来源配额按 `2:1:1` 计算，实际来源统计以规则检查后的有效候选为准。
- 任务记录包含 `user_input_facts`，该字段只保存用户自然语言明确给出的事实；普通几何数值写入 `geometry_reference`，只作为设计中心和几何包络依据；明确固定、限定、保持不变、必须等于的字段级几何数值写入 `fixed_geometry`。候选生成 LLM 读取该字段、项目运行时知识库/知识图谱片段、LLM 候选数量、输出字段要求和系统候选字段约束。字段约束只限定材料库、参数范围和单位格式，不写成用户事实。
- LLM 候选由自然语言表格解析得到，候选编号不参与材料解析；`geometry_reference` 不覆盖模型候选参数，`fixed_geometry` 覆盖对应候选参数；模型候选行和回答原文保存在候选追踪字段中。
- LLM、案例迁移和 DOE 三路候选按材料、几何变量和铺层表达式去重；结构等价的重复方案不进入候选池，候选池缺口由 DOE 补足。
- 候选生成写入 `generation_audit`，记录三路初始配额、原始输出数、规则有效数、实际进入候选池数量、规则过滤数量、结构去重数量、DOE 补足数量、DOE 采样轮次和过滤原因摘要；该审计随候选池进入 GUI，并通过 `candidate_generation_audit` 事件写入工作流事件库。
- 会话候选使用 `candidate_id=display_name=TMP_N`；进入有限元后正式输入使用 `candidate_id=display_name=C<N>`，并以 `session_candidate_id` 回溯会话候选。案例记录顶层、案例设计和正式有限元结果都保留正式 `candidate_id/display_name`；正式有限元结果文件和案例记录中的 `abaqus_results` 保留会话回溯字段，便于离线重生成报告。
- LLM 候选缺少材料、长度、半径、厚度、alpha、beta 或缺陷比时不进入候选池；案例迁移来源必须提供完整候选几何；DOE 使用参数域生成完整候选并闭合候选池数量。
- 知识库读取本项目 `knowledge/runtime` 和 `knowledge/chroma_db`，支持上传资料、解析、token 分块、内容去重、向量索引、实体关系抽取、检索证据预览和流水线状态显示。
- `config/app_config.yaml` 中 `project_knowledge` 配置当前指向 `knowledge/runtime/rag/rag_chunks.jsonl`、`knowledge/chroma_db` 的 `csdm_cph_project_knowledge` collection、`knowledge/runtime/kg` 和 `knowledge/runtime/manifest.json`。
- RAG 分块参数为 `chunk_token_size=512`、`chunk_overlap_tokens=64`、`min_chunk_tokens=80`，完全相同 chunk 按 `content_hash` 去重。
- 材料库、参数范围和代理公式已写入 `config/`。
- `workflow/` 已提供 LangGraph 状态图运行时、智能体职责契约、SQLite 事件存储、工具注册和快照恢复接口；现有 PyQt6 主对话流程通过该运行时推进，GUI“监控”页可刷新最近运行记录并恢复运行状态，项目页保留人工筛选、有限元校核和重置入口。恢复运行状态只读取本地运行库，不重新调用 LLM 或 Abaqus。
- 有限元校核已接入 `workflow/simulation_queue.py` 作业队列，记录候选入队、运行、成功、失败、正式编号、结果摘要和错误信息。
- 知识回流已作为状态图节点 `persist_knowledge` 独立运行，写入 `knowledge_updates` 快照字段，并通过 `KnowledgeMemoryAgent` 工具事件审计。
- PyQt6 核心工作台包含“智能体流程”面板，读取工作流运行事件、状态快照和有限元队列，展示运行摘要、LangGraph DAG、状态图、节点产物、智能体职责契约、诊断信息、LLM 后端配置状态、LLM 后端实时检测结果、LLM 调用轨迹、有限元队列和工具调用审计，并可导出单次运行审计报告。
- PyQt6 右侧“候选”页展示候选来源构成、三路初始配额、规则过滤、结构去重和 DOE 补足审计。
- PyQt6 右侧“追踪”页展示 TMP 会话候选、正式 C 编号、代理预测、FEM 结果、代理误差、CASE 回流状态和报告纳入状态之间的对应关系。
- PyQt6 右侧“报告”页读取当前会话报告或 `data/results/latest_report.md`，展示 Markdown/PDF 路径、LLM 工程解释使用状态和 Markdown 正文预览。

## LLM 调用边界

- `TaskParser` 不调用 LLM，候选池数量、初筛保留数、载荷、几何参考值、固定几何约束和目标压力由规则解析得到。
- `CandidateGenAgent` 调用领域主模型生成 LLM 来源候选；输入为系统整理后的工程任务书，包含用户已给事实、项目运行时知识库/知识图谱片段、LLM 候选数量、输出字段要求和系统候选字段约束，不把默认压力、默认材料或默认几何范围写成用户事实。
- `ReportGenAgent` 的任务事实、候选编号、压力数值、排序和有限元结论由结构化数据确定性生成；工程解释与制造建议可调用 LLM 做定性解释，输出出现结构化输入之外的新数值、阈值、材料牌号时先做约束清理，清理后仍不合规或调用失败时使用确定性解释。报告模板会清理 LLM 自带的重复章节标题，最终只保留一组“工程解释与制造建议”章节。
- `ReportWidget` 不修改报告内容，不调用 LLM，只预览 `ReportGenAgent` 已生成的 Markdown 内容或最新落盘报告文件。
- `ScreenerAgent`、`FEMAgent`、`KnowledgeAgent`、`ConversationFlowController` 不调用 LLM。

## 工作流运行时

- `DesignWorkflowRuntime.start()` 启动任务并运行到代理初筛人工确认点。
- `DesignWorkflowRuntime.continue_after_confirmation()` 根据当前等待确认项继续推进代理初筛、有限元校核、知识回流或报告导出。
- `DesignWorkflowRuntime.resume()` 通过 `run_id` 读取最近状态快照；`WorkflowEventStore.list_runs()` 为 GUI 提供最近运行摘要。
- `WorkflowEventStore` 写入 `data/runtime/workflow_runtime.sqlite3`，记录工作流运行、节点事件、工具调用事件、人工确认事件和最新状态快照。
- `ToolRegistry` 将任务解析、候选生成、代理初筛、有限元、知识回流和报告导出注册为可审计工具，工具事件记录输入摘要、输出摘要、耗时和失败原因。
- `SimulationJobQueue` 使用同一 SQLite 运行库记录 `simulation_jobs`，当前为本地串行执行记录，后续可扩展为工作站并行作业调度。
- `workflow/run_audit.py` 读取工作流快照、事件审计和有限元作业队列，生成 `data/results/run_audit_<RUN_ID>.md`，用于复核候选来源、LLM 调用、FEM 队列、知识回流和阻断诊断。
