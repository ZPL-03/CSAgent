# CSAgent 项目状态

## 当前事实

- 项目目标为复合材料外压圆柱耐压壳智能设计。
- 主流程为耐压壳多智能体智能设计编排。
- 用户可见产品名为 `CSAgent 多智能体智能设计平台`。
- LLM 配置读取项目根目录 `.env`，主模型使用 `LLM_PRIMARY_URL`、`LLM_PRIMARY_API_KEY`、`LLM_PRIMARY_MODEL_NAME`，回退模型使用 `URL`、`API_KEY`、`MODEL_NAME`。
- LLM 后端按主模型优先、回退模型补充的顺序调用；候选生成和报告解释会记录 `llm_call_trace` 事件，事件只包含后端名称、模型名称、状态、耗时、返回字符数和错误摘要，不包含 URL、密钥或提示词正文。
- GUI 顶部当前模型标识读取 `llm_call_trace` 事件，显示本次调用实际使用的领域主模型、回退模型或失败状态；同一状态会写入工作台运行日志和监控日志。
- 监控页提供运行审计入口；LLM 健康检查由本地审计脚本或人工动作触发，检测结果不展示 URL、密钥或提示词正文；运行审计报告写入 `data/results/run_audit_<RUN_ID>.md`。
- `scripts/release_audit.py` 是本地质量检查入口，覆盖产品命名、本地运行产物隔离、密钥忽略规则、知识库运行时路径、UI 展示资产、案例编号连续性、最新报告标题、GUI 深浅主题渲染可选检查和 LLM 连通性可选检查。
- PyQt6 主界面默认为简体中文，“设置”页支持 English、跟随系统、深色工程和亮色工程；界面偏好写入 `data/runtime/ui_settings.json`，不进入 Git。主程序启动时优先加载 `HarmonyOS Sans SC`、`Noto Sans SC` 和 Windows 中文字体，避免中文控件和可视化图注显示为方块。
- PyQt6 主界面采用 `QMainWindow + QSplitter + QStackedWidget` 工程工作台布局：顶部为系统身份栏、页面导航和当前模型标识；语言和主题选择位于“设置”页；左栏展示六个智能体状态、任务队列和知识连接；中央 Stack 包含工作台、知识库、监控、设置；工作台上部展示候选池及设计详情/来源审计，下部为对话交互区；`ORCHESTRATOR` 承载需求解析、任务编排和人工确认，不单独显示第七个“需求解析”智能体；右栏展示实时视口、会话指标、运行日志、阶段报告、会话数据导出和报告打开入口。实时视口在本机 OpenGL 可用时使用 PyVista 交互视图，支持旋转、缩放、平移、双击重置、按钮重置视角和适配窗口。设置页提供主/回退 LLM、Abaqus、候选来源比例、人工确认节点、RAG/KG 分块和向量索引等本地 YAML 配置表单；右栏展示主模型、回退模型、Abaqus、RAG/KG、候选来源比例和人工确认节点的配置健康状态；密钥仍由 `.env` 管理，GUI 不显示密钥正文。
- 顶部品牌标识显示为 CSAgent 图形徽标、`CSAgent` 主标题和“多智能体智能设计平台”副标题；界面不包含登录头像。左侧智能体卡片支持完成、运行中、失败、等待四类状态灯，状态图位于监控页的工作流审计面板。工作台对话流按内容自适应气泡宽度，短消息不拉满面板，用户输入显示在右侧并保留头像标识。
- 右侧实时结果区的“导出数据”入口写入 `data/results/session_export_<RUN_ID>.json` 和 `data/results/session_trace_<RUN_ID>.csv`，用于复核当前会话任务、候选、初筛、FEM、知识回流、报告元数据和 TMP-C-CASE 追踪关系。
- 工作站领域模型接口示例为 `LLM_PRIMARY_URL=https://csllm.ipen03.com/v1` 和 `LLM_PRIMARY_MODEL_NAME=csllm`。
- GUI 主流程只使用自然语言设计需求，需求中必须明确包含候选池总数和初筛保留数。
- 工作台从同一会话状态读取结构化任务、用户已给事实、几何约束、候选生成控制参数、初筛控制参数和事实边界；这些字段只用于展示、候选约束和审计，不由界面改写。
- LLM、案例迁移和 DOE 的初始来源配额按 `2:1:1` 计算，实际来源统计以规则检查后的有效候选为准。
- 任务记录包含 `user_input_facts`，该字段只保存用户自然语言明确给出的事实；明确给出的几何数值默认写入 `fixed_geometry`，作为候选生成和有限元输入必须满足的条件；只有字段附近出现“约、参考、附近、设计中心、左右”等参考语义时，对应字段才写入 `geometry_reference`。候选生成 LLM 读取该字段、合并 RAG/KG 检索片段、LLM 候选数量、输出字段要求和系统候选字段约束。字段约束只限定材料库、参数范围和单位格式，不写成用户事实。
- LLM 候选由自然语言表格解析得到，候选编号不参与材料解析；`geometry_reference` 不覆盖模型候选参数，`fixed_geometry` 覆盖对应候选参数；模型候选行和回答原文保存在候选追踪字段中。
- LLM、案例迁移和 DOE 三路候选按材料、几何变量和铺层表达式去重；结构等价的重复方案不进入候选池，候选池缺口由 DOE 补足。

## LLM 调用边界

- `TaskParser` 不调用 LLM，候选池数量、初筛保留数、载荷、几何约束、几何参考和目标压力由规则解析得到。
- `CandidateGenAgent` 调用领域主模型生成 LLM 来源候选；输入为系统整理后的工程任务书，包含用户已给事实、合并 RAG/KG 检索片段、LLM 候选数量、输出字段要求和系统候选字段约束，不把默认压力、默认材料或默认几何范围写成用户事实。
- `ReportGenAgent` 的任务事实、候选编号、压力数值、排序和有限元结论由结构化数据确定性生成。LLM 接收真实候选几何、逐候选铺层、数值指标、服务与目标压力校核状态、Riks 状态和分析范围，用于定性工程解释；不复述数值不表示数据缺失，已完成的分析不应描述为尚未执行。LaTeX 数学片段通过语法解析转换为可排版文本，再检查数值和材料，不因可转换的数学标记拒绝解释；未闭合或不支持的数学命令明确报告。输出出现结构化输入之外的新数值、阈值或材料牌号时先做约束清理，清理后仍不合规或调用失败时记录原因并使用确定性解释。每类报告分别保存 `llm_explanation_used`，不以一次 LLM 请求成功代表所有解释均被采用。报告模板清理重复章节标题；手动生成的报告同步写入运行快照，恢复入口读取同一报告。
- `ReportWidget` 不修改报告内容，不调用 LLM，只预览当前会话明确提供的 Markdown 内容或路径。
- `ScreenerAgent`、`FEMAgent`、`KnowledgeAgent`、`ConversationFlowController` 不调用 LLM。

## 工作流运行时

- `DesignWorkflowRuntime.start()` 启动任务并运行到代理初筛人工确认点。
- `DesignWorkflowRuntime.continue_after_confirmation()` 根据当前等待确认项继续推进代理初筛、有限元校核、知识回流或报告导出。
- `DesignWorkflowRuntime.resume()` 通过 `run_id` 读取最近状态快照；`WorkflowEventStore.list_runs()` 为 GUI 提供最近运行摘要。
- `WorkflowEventStore` 写入 `data/runtime/workflow_runtime.sqlite3`，记录工作流运行、节点事件、工具调用事件、人工确认事件和最新状态快照。
- `workflow_runs.status` 由最新快照推导，状态包括 `running`、`waiting`、`paused`、`failed` 和 `completed`；监控页、恢复入口和运行审计使用同一状态字段。
- `ToolRegistry` 将任务解析、候选生成、代理初筛、有限元、知识回流和报告导出注册为可审计工具，工具事件记录输入摘要、输出摘要、耗时和失败原因。
- `workflow/agent_contracts.py` 为六个运行时智能体声明输入输出、LLM 边界、记忆策略、事件策略和失败策略；发布审计会检查契约与工具注册、事件库和仿真队列保持一致。
- `SimulationJobQueue` 使用同一 SQLite 运行库记录 `simulation_jobs`，当前为本地串行执行记录，并保留工作站并行作业调度所需的候选编号、正式编号、状态、结果摘要和错误字段。
- `workflow/run_audit.py` 读取工作流快照、事件审计和有限元作业队列，生成 `data/results/run_audit_<RUN_ID>.md`，用于复核候选来源、LLM 调用、FEM 队列、知识回流和阻断诊断。
- 自动回归中的自然语言验收覆盖中文和英文输入：任务解析、候选生成和代理初筛进入运行时人工确认链路；有限元、知识回流和报告阶段使用确定性适配器，检查候选去重、TMP-C 回溯、仿真队列事件、知识回流状态、报告路径和 SQLite 快照。真实 csllm 与本地 Abaqus 的端到端证据见“验证边界”中的两轮 GUI 会话，不以适配器结果代替真实求解结果。
